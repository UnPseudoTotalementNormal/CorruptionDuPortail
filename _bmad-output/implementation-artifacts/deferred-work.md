## Deferred from: story-5.0d (2026-06-11)

- **Static/serializable façade reads left on `GameManager.instance` (same per-NM hazard as the dispatcher above).** 5.0d migrated 70/161 reads to `GameManager.For(NetworkManager)` but, by the verify-and-reclassify rule, left these on the static façade because they have no `NetworkManager` context to resolve with: `TargetUtils.cs` (4, static class), `PowerEffectDispatcher.cs` (4, static class — pairs with the 5.0c entry above), `WinningConditions/{WAnomalyCorruption,WChosenChainedAllAnomaly,WMarginalIsChainedWin,WOmniscienceHackedCharacter}.cs` (5 total, serializable, legacy parameterless `CheckCondition()`). Revisit when threading an NM (or injection) reaches these types — `TargetUtils`/`PowerEffectDispatcher` need an NM parameter through their public static API; the W*.cs need either the snapshot path to fully replace the legacy `CheckCondition()` or an NM on the virtual signature (touches the differential harness).

- **THE BIG ONE — real despaghettification is NOT done by the de-singleton work (Poyo flagged, 2026-06-11).** The 5.0x stories trade a *process-global* singleton for a *per-NetworkManager* registry (`For(NetworkManager)`). That is **Service Locator, not decoupling**: powers/board/characters still reach a globally-resolved manager via an *implicit* dependency, and `GameManager` is still a **God Object** (holds `gameStates` + `characterManager` + `gameInfoRevealer` + `chainingManager` + game loop + RPC dispatch + UI bars). `For()` is behaviour-preserving scaffolding that (a) unblocks the multi-client test fixture and (b) makes the dependency addressable per-instance so it can *later* be swapped for injection. The actual despaghettification pass, to schedule AFTER 5.0e proves coexistence:
  1. Inject `GameManager`/`CharacterManager` into powers via `Initialize(...)` — the model already exists in this codebase: GameStates receive an injected `gameManager` (see `GameState.gameManager`, assigned in `GameManager.SetupGameStates`). Replace `For(NetworkManager)` lookups in powers with a declared, injected reference.
  2. Split the `GameManager` God Object: have callers depend on **narrow interfaces** (e.g. `ICharacterQuery`, `IRevealService`, `IGameLoop`) instead of the whole manager, so each system declares only what it needs.
  Without this explicit pass, the powers stay coupled to a global lookup forever — just per-NM instead of process-global. It is intentionally OUT of the current plan (5.0a–5.0e target only issue #50 unblock).
